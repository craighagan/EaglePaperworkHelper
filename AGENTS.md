# AGENTS.md

Instructions for AI coding agents (and people) changing this repository. Read this before editing. [README.md](README.md) is the user guide; [INSTALL.md](INSTALL.md) covers hosting; [todo/](todo/) lists open work.

## What this is

Offline helpers for the BSA **Eagle Scout Service Project Workbook No. 2023a**. Scouts (mostly 14–17, many with little tech experience) type answers into a workbook page, save a backup file, and fill the official PDF. Everything runs in the browser.

## Hard rules

Breaking any of these is a defect, even if the tests pass.

1. **No build, no install, no server code.** Pages must work when double-clicked (`file://`) and from a plain static https server.
2. **Classic scripts only.** Browsers block ES modules on `file://`. No `import`/`export`, no `type="module"`, no bundler.
3. **No inline scripts or handlers.** Each page has a content security policy (CSP) meta tag with `script-src 'self' file:`. Put code in `lib/*.js`. The pages that draw PDFs also allow `'wasm-unsafe-eval'` in `script-src`, only so the bundled JPEG 2000 decoder (`vendor/pdfjs/openjpeg-wasm.js`) can run; never add `'unsafe-inline'` or `'unsafe-eval'`.
4. **No network requests** except the optional download of the blank official PDF, pinned to the exact URL in `connect-src` of `FillOfficialPDF.html`. No CDNs, fonts, analytics, or telemetry.
5. **Never put user data into HTML.** Build DOM with the `h()` helper (`lib/workbook-common.js`) or `el()` (page scripts), which use text nodes. No `innerHTML`, `insertAdjacentHTML`, or `document.write`.
6. **Never fill signatures or approval dates.** Scans of signed pages are inserted as pictures, never altered or placed over the official page. Printed names beside approval lines are the only approval-area boxes filled, and the user can opt out.
7. **Don't add, change, or misstate Scouting requirements.** Labels that echo the official workbook must match its text. Check against the PDF (see "Official text" below). Plain-language rewording in the Guided workbook must keep the meaning.
8. **No real Scout data in the repo, ever.** Not in fixtures, tests, screenshots, examples, or commit messages. Use `tests/fixtures/sample-workbook.json` (fictional). `.gitignore` blocks `*.json` except the two named fixtures, and blocks all PDFs.
9. **Keep backup-file keys stable.** Older backup files must keep opening. Add keys; never rename or remove them. `mergeWithDefaults` fills in missing keys and keeps unknown ones.
10. **Don't hand-edit `vendor/pdfjs/`.** It is generated by `tools/vendor-pdfjs.cjs`.
11. **Tips are guidance, never requirements.** Text in `lib/tips.js` must not add, change, or misstate a rule. Anything from a council, coach, or blog gets `advice: true`. Examples are made up and generic. Paraphrase sources, and list them in `docs/guidance-sources.md`.

## Layout

| Path | What it does |
| --- | --- |
| `index.html` | Home page. No scripts. |
| `EagleWorkbook-guided.html` + `lib/guided-workbook.js` | Guided workbook: six stages (the last is Signed Pages), plain language, examples. |
| `EagleWorkbook.html` + `lib/classic-workbook.js` | Classic workbook: official wording and order. |
| `lib/workbook-common.js` | Shared by both workbooks: `defaults()` (the data model), browser storage, backup files (save, open, share), the "keep your work safe" panel, print draft, form helpers (`createForm`, including the "? Tips" buttons), `h()`. |
| `lib/attachments.js` | Signed pages, attachments, and links: the three signature slots (`SLOTS`, PDF pages 15, 23, 29), photo and PDF → JPEG pages, IndexedDB storage, pictures in backup files (`withPictures`, `absorb`), and the submission copy (`buildSubmission`, a small JPEG-and-text PDF writer). Runs in the browser and in Node tests. |
| `lib/tips.js` | The text behind each "? Tips" button, keyed by backup-file path. Limits on length and the official page of each box are checked by tests. |
| `FillOfficialPDF.html` + `lib/fill-page.js` | Fill the official PDF from a backup file or a saved draft. |
| `BackupFromPDF.html` + `lib/backup-from-pdf-page.js` | Read a filled (fillable) workbook PDF back into a backup file. Flattened PDFs are intentionally unsupported. |
| `lib/official-pdf.js` | Backup → PDF field mapping (`buildFieldValues`), filling (`fillOfficialPdf`), reading back (`readBackupFromPdf`, `reverseMap`), totals, date and money parsing, warnings in plain words (`describeField`). Runs in the browser and in Node tests. |
| `vendor/pdfjs/` | pdf.js 5.4.296, converted to classic scripts plus a font fix and a patch that reads the JPEG 2000 decoder (`openjpeg-wasm.js`, base64) from a bundled script instead of fetching it. Without it, the cover art and logo vanish from the submission copy. Generated. |
| `tools/vendor-pdfjs.cjs` | Rebuilds `vendor/pdfjs/` from pinned, SHA-256-checked downloads. |
| `tools/screenshots.cjs` | Regenerates `docs/*.png` from the fictional sample. |
| `tests/` | `run-tests.cjs` (unit + real PDF), `browser-e2e.cjs` (headless Chrome), `pdfkit-check.swift` (macOS Preview engine), fixtures. |

Script load order matters. Workbook pages load `lib/official-pdf.js`, then `lib/tips.js`, then `lib/attachments.js`, then `lib/workbook-common.js`, then the page script; they load pdf.js only when someone adds a PDF scan. `FillOfficialPDF.html` loads `vendor/pdfjs/pdf.worker.js`, then `vendor/pdfjs/pdf.js`, then `lib/official-pdf.js`, then `lib/attachments.js`, then its page script. pdf.js runs its worker on the main thread through `globalThis.pdfjsWorker`; there is no Web Worker.

Browser storage keys: `eagle_workbook_guided_v1` and `eagle_workbook_v1` (drafts), each with `_saved` and `_backup` timestamps. Scanned pages are JPEGs in IndexedDB database `eagle_workbook_files` (store `pages`, keyed by page id), never in localStorage. Backup files carry them as base64 in `attachments[].pages[].jpeg`.

The official PDF forbids adding pages (document assembly), so the submission copy is a new PDF of drawn pages, like printing. Don't try to insert pages into the official file.

## Commands

Requirements: Node.js 22+, no `npm install`. Browser tests need Chrome or Chromium.

```bash
node tests/run-tests.cjs        # unit tests, page checks, fill + read back the real official PDF
node tests/browser-e2e.cjs      # drives every page from file:// in headless Chrome
node tools/screenshots.cjs      # regenerate docs/*.png (fictional data only)
node tools/vendor-pdfjs.cjs     # rebuild vendor/pdfjs (network)
```

- The first `run-tests.cjs` run downloads the official PDF to `tests/.cache/` (git-ignored) and checks its SHA-256. Offline, point `EAGLE_PDF` at a copy.
- `CHROME_NO_SANDBOX=1`: only in disposable environments (containers, agent sandboxes) where Chrome's sandbox can't start. Never on a personal machine. `CHROME=/path`: a non-default Chrome.
- `EAGLE_ONLINE=1` also tests "Get the official PDF for me" against scouting.org.
- `EAGLE_LOCAL_BACKUP=/path/to/backup.json` round-trips one of the maintainer's own files and prints counts only. Never copy that file into the repo.
- Ghostscript (`gs`) and Poppler (`pdftotext`), if installed, are used to check that typed answers are visible. On macOS the browser tests also check Apple PDFKit.

Both test scripts must pass before you commit.

## Common changes

### Add an answer

1. Add the key with a `''` default in `defaults()` in `lib/workbook-common.js`. If it is a date, add its key name to `DATE_KEY` in `lib/official-pdf.js` (and use `type: 'date'` for the input); if it is a dollar amount, add it to `MONEY_KEY`. Reading back depends on these lists.
2. Add the input to **both** `lib/guided-workbook.js` and `lib/classic-workbook.js` with `f.field(label, 'path.to.key', options)`. The Classic label should follow the official wording.
3. Map it in `buildFieldValues` with `put('<PDF field name>', get('path.to.key'))`. Field names are in `tests/fixtures/official-2023a-fields.json`.
4. Add a plain-language label to `LABELS` in `lib/official-pdf.js` so warnings can name the box.
5. Reading back is automatic for one-box answers (`reverseMap` derives it from `buildFieldValues`). Phases, radio buttons, and totals have hand-written rules in `backupFromValues`.
6. Run both test scripts. The "every answer" tests build their data from `defaults()`, so they cover the new key without edits. Add a specific assertion if the mapping has a rule.

### Add or change a tip

1. Edit `lib/tips.js`. The key is the backup-file path of the box (for a table or section, use a name like `plan.hazards` and set `for` to one box inside it). Fields: `text` (what goes here), `good` (a made-up example), `avoid` (one common mistake), `where`, `advice`.
2. Set `where` to the printed page of the *box* in the official workbook, such as `Proposal Page C` (the panel says "This box is on: …"). If the tip cites a rule from a different page, name that page in the tip text. Look the page up with the commands under "Official text". A test checks it against the real PDF, and also checks lengths (text 200, example 260, avoid 150, 560 in all).
3. Set `advice: true` unless the workbook itself says it. Never write "must" or "required" for advice.
4. Fields pick up a tip by path automatically (`f.field(label, path)`). For a table or section, add `f.tipBox('key', 'name for screen readers')` inside the section (put it next to the content it explains, not always first) in both `lib/guided-workbook.js` and `lib/classic-workbook.js`. A tip with an example (`good`) replaces any `example:` option on its field.
5. Add the source to `docs/guidance-sources.md`. If a source disagrees with the workbook, follow the workbook and say so there.
6. Run both test scripts, then do a review (see "Review panel").

### Change wording

Keep the terms consistent everywhere (pages, messages, README, index):

- **backup file**: the `.json` file. Say "backup file" in the UI; mention `.json` only to help someone find it.
- **draft**: what a workbook page auto-saves in the browser.
- **Guided workbook** / **Classic workbook**.
- **Fill the official PDF**, **Make a backup file from a PDF**, **Print a draft**.
- **official workbook** or **official PDF**: the scouting.org file.

Write for a 15-year-old: short sentences, everyday words, and the next action stated plainly. Error messages say what happened and what to do next.

### Official text

```bash
qpdf --decrypt tests/.cache/EagleProjectWorkbook2023a.pdf /tmp/dec.pdf
pdftotext -layout /tmp/dec.pdf /tmp/dec.txt          # text (extraction drops some letters; read carefully)
qpdf --json --json-key=acroform /tmp/dec.pdf          # field names, pages, positions
```

### Upgrade pdf.js

Check pdfjs-dist security advisories first. In `tools/vendor-pdfjs.cjs`, update `VERSION`, the source hashes in `SOURCES`, and `LICENSE_SHA256`. If the script reports that the `FONT_FALLBACK` target was not found exactly once, update its `find` string for the new version. Then run it and both test scripts.

### A new official workbook

Field names may change. Update `OFFICIAL_PDF_URL`, `OFFICIAL_SHA256`, `WORKBOOK_VERSION`, and `SIGNATURE_FIELDS` in `lib/official-pdf.js`. Then update the field list fixture, the mapping, the `connect-src` URL in `FillOfficialPDF.html`, and the links in the pages and docs. Run both test scripts.

### Screenshots

Run `node tools/screenshots.cjs` after any visible change to the Guided Proposal stage or the Fill page. It uses only the fictional sample.

## Review panel

Before committing any change users will see, run a review panel. That means wording, tips, page layout, field mapping, PDF filling or reading, storage, privacy, or vendored code. Typo fixes and notes in `todo/` don't need one. Independent reviewers in a clean context find mistakes you can't see in your own work. Earlier rounds on this project found answers printing blank in some PDF viewers, totals that could print wrong, labels that didn't match the official box, and a misstated fundraising rule.

### Steps

1. **Make the tests pass first** (`node tests/run-tests.cjs`, `node tests/browser-e2e.cjs`). Don't commit yet.
2. **Spawn one reviewer per lens, in parallel, each in a clean context** (a sub-agent that has not seen your work). The four lenses:
   - **Engineering and PDF:** correctness and edge cases in `lib/`, regressions, test quality, the pdf.js build, behavior in other viewers.
   - **Teen, parent, and accessibility:** can a 15-year-old finish the task? Wording, first action, error messages, 390px phone width, keyboard, screen reader, contrast, data-loss risks.
   - **Security, privacy, and licensing:** data exposure, CSP, injection, untrusted files, real personal data in the tree or history, license notices, supply chain.
   - **Eagle advancement and official-text fidelity:** every label, tip, and field mapping against the official workbook text. Nothing added, changed, or misstated. Answers land in the right official box.
   Add a **research checker** when you added guidance from outside sources: it opens the cited sources and confirms each paraphrase is accurate and marked as advice.
3. **Give each reviewer a prompt like this** (fill in the brackets):

   ```text
   You are a reviewer on a review panel. Lens: [lens and what it checks]. Review independently.
   DO NOT modify repository files; scratch work only in /tmp/eph/[name]/.
   Repository: [absolute path]. Read AGENTS.md and README.md first.
   What changed: [summary; run `git status` and `git -P diff`]. [Round 2 only: previous reports are at /tmp/eph/[files]; verify each finding.]
   Constraints: static offline pages, works from file://, teen audience, no network, guidance never adds requirements.
   Run the tests: `node tests/run-tests.cjs` and `CHROME_NO_SANDBOX=1 node tests/browser-e2e.cjs` [drop the sandbox flag on a normal machine].
   Probe for yourself: [specific things to try]. Verify, don't speculate; give file:line and a repro for each finding.
   Severity: BLOCKING = a wrong answer in a wrong box, a misstated requirement, lost work, a privacy leak, or broken for users;
   IMPORTANT = fix before release; MINOR = polish.
   Write the full review to /tmp/eph/[report].md and return it:
   ### Challenges (each: where, problem, what good looks like, severity) / ### What's strong / ### Verdict: PASS, CONDITIONAL PASS, or NEEDS WORK
   Only real, verified findings. Don't pad.
   ```

4. **Triage the reports yourself.** Reproduce each finding before fixing it. If a finding is wrong, say why and skip it. Don't apply advice blindly, and never let a fix add a requirement.
5. **Fix, then run round 2 with fresh reviewers.** Their job: for every earlier finding say FIXED, NOT FIXED, or PARTIAL with evidence, and look for new problems the fixes caused. Repeat until no BLOCKING or IMPORTANT findings remain.
6. **Final check** (one verifier): tests pass, one clean history, the right author email, nothing secret or personal staged.
7. **Record it.** Put a short summary in the commit message. Put deferred MINOR items in `todo/`.

### If it goes wrong

- A sub-agent call that fails ("Tool execution failed"): retry once, then run fewer reviewers at a time. If a lens still can't run, do that lens yourself with the same checks and say so in the commit message.
- If a skill named `review-panel` is installed, you can use it to cast the panel (contexts "Technical design" and "Volunteer / youth organization" fit). The prompt above is the baseline either way.
- Reviewers may disagree. Keep both views, decide with the maintainer's goals in mind (the Scout's success, accuracy to the official workbook, privacy), and note the decision.

## Git

- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), imperative subject, body explaining why.
- The repository's local git identity is set; don't change it.
- Don't push, rewrite pushed history, or force-push unless the maintainer asks. Push with `git push origin main`, never `--mirror`.
- Record ideas and follow-ups in `todo/` instead of doing unrequested work.

## Reviewer guardrails

- Reviewers never open, quote, or summarize a real Scout's backup file or PDF. Use the fixtures.
- Write review reports to a private temp folder (for example `/tmp/eph/<panel>/`) and delete them after the fixes land.
- Never put a real Scout's name, address, project theme, or beneficiary in tests, fixtures, tips, or screenshots. The tip test blocks emails, phone numbers, and street addresses, but it can't catch names, so check by eye.
